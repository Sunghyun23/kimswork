# Local development

Run the separate bootstrap from repository root. It clones only reviewed exact commits into ignored third_party paths; it refuses a different or modified checkout. The existing official MPC SDK and released products are not changed.

`tools/check_environment.py` reports Rust/Cargo and packaging dependencies without installing anything. The pinned SDK requires Rust1.97 or later; do not lower its rust-version to make an old compiler pass. Prefer a Sample-specific toolchain/cache under ignored `.sdk-tools/mpc-sample/`; do not replace the global Rust default.

After the correct compiler is available, run SDK host checks in a scratch copy, using an external CARGO_TARGET_DIR. SDK Cargo.lock/cache generated by tests must stay out of source commits. Before any device package, use the SDK's documented build-mod.sh with its ARM64 linker and ELF/glibc/symbol checks. Keep the ABI/glibc target and exact firmware guard; a macOS library is not a device mod.

A product requires an approved purpose/name/vendor, then independent source/state/tests and an autorun package. First smoke check should preserve normal audio and forward every pad/button unchanged. Test host logic before hooks; use a legitimately supplied firmware image for optional emulation and never commit firmware or its extracted files. Installing SampleBoot or a mod is a later operation, after firmware/fingerprint, SD backup and owner-work checks.

## Isolated tools on this Mac

The Sample-specific Rust1.97.0toolchain, Rust ARM64 Linux target and LLVM tools were installed under ignored `.sdk-tools/mpc-sample/`. The user's global Rust remains1.88.0. `development_environment.py` chooses the local compiler and LLVM binaries only for these child commands. It reuses the existing SDK's Zig0.17.1executable without changing that SDK or its build rules. On another computer, provide a suitable Zig on PATH if that existing compiler cache is unavailable.

From repository root, these commands reproduce the isolated Rust setup without changing the global default:

```sh
RUSTUP_HOME="$PWD/.sdk-tools/mpc-sample/rustup" CARGO_HOME="$PWD/.sdk-tools/mpc-sample/cargo" rustup toolchain install 1.97.0 --profile minimal --no-self-update
RUSTUP_HOME="$PWD/.sdk-tools/mpc-sample/rustup" CARGO_HOME="$PWD/.sdk-tools/mpc-sample/cargo" rustup component add --toolchain 1.97.0 rustfmt clippy llvm-tools
RUSTUP_HOME="$PWD/.sdk-tools/mpc-sample/rustup" CARGO_HOME="$PWD/.sdk-tools/mpc-sample/cargo" rustup target add --toolchain 1.97.0 aarch64-unknown-linux-gnu
python3 mpc-software/mpc-sample/tools/check_environment.py
python3 mpc-software/mpc-sample/tools/check_sdk.py
```

The host-check runner copies the pinned source into a temporary local folder and writes logs/reports only under ignored `.sdk-tools/mpc-sample/validation/`. It never patches the SDK or connects to hardware. `cargo check --target` checks ARM64 code generation prerequisites; it does not certify a linked product `.so` or an installed mod. Such product-level checks follow after choosing the first product.

## MPC Sample autonomous QA workflow — owner approved 2026-11-22

- During Sample development, prefer the USB QA runtime agent for own-code upload, checksum verification, app-only restart and active-DRM screenshot capture. Do not repeatedly ask the owner to export SD/reboot when this tested path is reachable. This authorizes iterative QA-session restarts; preserve owner work and never overwrite an owner session for a test.
- The current Loop Club hardware uses direct autorun, without SampleBoot/menu. Keep the previous boot tree in verified recovery backups. No firmware flashing, internal persistent-service changes or unrelated product changes are implied.
- Device endpoints are current connection details, not permanent platform assumptions: QA app8090 and isolated transient agent8091 over the verified USB interface. Check device/build identity before mutation. Keep these opt-in tools out of normal/public builds.
- Build with the pinned unmodified SDK; verify ARM64/glibc/fingerprint and payload SHA. Stage a new runtime inode, preserve the working library, restart only ac50 and verify new PID, actual active-DRM screen and intended behavior. Roll back on failed readiness; the independent agent must survive app restarts.
- Runtime updates live in /run and disappear at power-off. Distinguish runtime testing from persistent SD installation. Native SD Card Access automation and hardware power reset are not implemented; do not claim them. Final persistent installation needs a verified card or a separately tested constrained install path.
- Own the QA pass: maintain a feature/interaction matrix, test normal/error/boundary paths, inspect actual screen readability/navigation and fix discovered bugs without repeatedly asking permission for routine reversible fixes. Keep screenshots/logs and exact tested build identity.
- Separate host tests, remote controller tests, actual device audio/screen evidence and physical controls. Queued remote buttons bypass the SDK physical button path; they cannot certify physical SEQ/pad/knob transport. Mark unavailable mic/line/pedal/physical checks explicitly; never mark all functions passed from a build or screenshots alone.
- Use a dedicated QA project directory for save/load tests, retaining user projects, audio, commercial packs and other mods/backups. Never publish private banks or QA state/captures.
